## 1. 세계 모델 (D5)

**처음부터 하나로 이어진 광장 섬 한 개** — `ui57.html`(C안) 계열.

| 안 | 파일 | 구조 | 판정 |
| --- | --- | --- | --- |
| A | `ui55.html` | 멤버마다 자기 땅이 따로 있고, 같이숲 진입 시 광장 주위로 날아와 **나무다리로 도킹** | ❌ 무효 |
| B | `ui56.html` | 다리 없이 멤버 땅끼리 맞붙는 초원, 구름 경계 | ❌ 무효 |
| C | `ui57.html` | 처음부터 완성된 단일 광장 + 줌 카메라 | ✅ **채택** |

**A·B가 무효인 이유**: 둘 다 "멤버마다 자기 땅이 있다"가 전제인데, 개인 공간이 사라져
**이어붙일 땅 자체가 없다**. 멤버 땅도, 그것을 잇는 다리·경계 연출도 없다.

**섬의 성장 표현**: 땅이 늘어나는 것이 아니라 **건물이 열리고 꾸밈이 쌓이는 것**으로 한다(D14).

### 1.1 투영 규격 — 2.5D 아이소메트릭 (2026-09-08 확정)

컨셉은 **2.5D 아이소메트릭**인데, **에셋 계약(`tasks/*.md`)에는 투영각 규정이 아예 없었다.**
그 결과 제작된 32종이 전부 **정면(elevation) 뷰**로 나왔다 — 캐릭터 스펙에 명시된 것도
`idle.svg = 정면 서기` 하나뿐이다. ui58 목업에서 광장을 아이소메트릭으로 그리자 이 불일치가 드러났다.

**확정 규격** (ui58 구현 기준):

| 항목 | 값 |
| --- | --- |
| 투영 | dimetric, 타일 **48 × 30 px** (가로:세로 1.6:1) |
| 격자 → 화면 | `x = OX + (gx − gy) × 24`, `y = OY + (gx + gy) × 15` |
| 섬 두께(절벽) | 52 px, 하단 16 px는 어두운 암반 띠 |
| 깊이 정렬 | 건물·캐릭터를 **한 리스트에 담아 `gx + gy` 오름차순**으로 그린다 |
| 명암 | 윗면 밝음 → 오른쪽 면 중간 → 왼쪽 면 어두움 |

**말랑하게 — 격자를 드러내지 않는다 (2026-09-08 추가).**
아이소메트릭을 타일 격자로 그리면 게임판처럼 각져 보이고, `catsoup.design.md`의
**"직선·정원 금지"** 규약과도 어긋난다. 실제로 첫 시도가 그랬다.

| 항목 | 규칙 |
| --- | --- |
| 지면 | **다이아몬드 타일을 그리지 않는다.** 섬 외곽을 유기적 곡선(Catmull-Rom, 반경에 sin 합 노이즈)으로 한 덩어리로 그린다 |
| 절벽 | 셀 단위 계단 금지. 앞쪽 호를 통째로 압출해 **하나의 곡면**으로. 색 3단(흙 `#CBA77C` → `#B18E64` → 암반 `#8E7150`) + 세로 결 |
| 길 | 타일 조각 금지, 중심에서 뻗는 방사형 별도 금지. **둘레길(링) + 짧은 지선**을 곡선 stroke로 |
| 건물 | 아이소 매스의 모든 코너를 라운드(반경 12~13). 각진 육면체 금지 |
| 잔디 결 | 격자 대신 풀포기를 흩어 배치 |

격자는 **좌표 계산에만** 쓰고 화면에는 드러내지 않는다.

**캐릭터는 정면 유지가 정답이다.** 아이소 지면 위의 정면 캐릭터는 이 장르의 표준이고
(쿠키런 킹덤도 그렇다), 포즈 4종 × 종족 3종은 **그대로 유효하다.**

**문제는 프롭이다.** 광장 프롭 8종과 개인 월드 프롭 12종은 정면 뷰라 아이소 지면 위에
놓으면 어긋난다. ui58에서는 7건물을 **전부 아이소 매스로 새로 작도**해야 했다.

| 구분 | 판정 |
| --- | --- |
| `chars/`·`chars-hq/` 캐릭터 | ✅ 그대로 사용 (정면 유지가 표준) |
| `props/common/` 8종 | ❌ 정면 뷰 — 아이소 재작도 필요 |
| `props/world/` 12종 | ❌ 정면 뷰 — 아이소 재작도 필요 (D5로 이미 보류 상태) |
| `bg/` 배경 2장 | ❌ 평면 배경 — 아이소 지면은 타일 생성으로 대체 |

**앞으로의 발주 스펙에는 투영각을 반드시 명시한다.** 이 한 줄이 빠져서 프롭 20종이
쓸 수 없는 각도로 나왔다.

**줌 카메라**: C안이 이미 갖고 있고, D34의 LOD가 여기에 얹힌다. `ui57.html`의 카메라는
RN 내장 `Animated.Value`(left/top/scale) 3개를 `Animated.parallel`로 구동하는 방식이
`catsoup-rn` 프로토에서 실기기 검증됐다.

## 1.2 화면 배치 — 쿠키런 킹덤 문법 (2026-09-08)

왕국 화면을 실측해 배치를 가져왔다. 정본은 `../cookierun-kingdom.design.md`.

| 규칙 | 내용 |
| --- | --- |
| **건물 위 이름표 금지** | 라벨이 월드를 덮으면 안 된다. 월드에 띄우는 건 **상태**뿐 — 모닥불 "N명 집중 중", 내 위치 |
| **하단 기능 바** | 건물 7종 아이콘 + 라벨. 잠긴 건 `Lv.n` 배지 + 흐림. presence는 아이콘 위 초록 점 |
| **지면이 화면을 채운다** | 기본 카메라에서 바다·절벽이 보이지 않는다(`scale 1.3`). **멀리 보기에서만** 섬 전체 + 바다 |
| **지면 밀도** | 빈 잔디를 남기지 않는다. 나무·관목·꽃무리로 채운다 |
| 좌우 세로 열 | 채택 안 함 — 세로 폰이고 기능 수가 적다 |

**에셋 크기 비율 (실측 기반, 2026-09-08).** 쿠키런이 풍성한 이유는 에셋이 커서가 아니라
**작아서**다. 건물이 화면의 1/10이면 30개가 들어가고, 1/4이면 7개밖에 못 들어간다.

| 항목 | 목표 |
| --- | --- |
| 최대 건물 폭 / 화면 폭 | **≤ 23%** |
| 일반 건물 폭 / 화면 폭 | **9~13%** |
| 캐릭터 높이 / 일반 건물 높이 | **1/3~1/4** |
| 화면 내 오브젝트 수 | **30개 이상** |
| 식생 배치 | 큰 나무는 **섬 바깥 링**에만. 건물 사이 안쪽은 꽃·바위·등불·관목 등 낮은 소품 |

지면(가용 공간)을 넓게 두고 에셋을 작게 두는 것이 "왕국" 느낌의 실체다.

**원칙 조정**: 2026-08-27의 "UI가 아니라 세계의 사물을 탭한다"는 **건물 탭 유지**로 살리고,
하단 바를 병행 진입점으로 둔다. 검증된 배치를 새로 발명하지 않는다.

## 2. 렌더 스택 (D35)

**결정: `react-native-svg` + `react-native-reanimated`. Skia는 도입하지 않는다.**

| 후보 | 판정 근거 |
| --- | --- |
| **react-native-svg + reanimated** | ✅ gromo `app/app-dev/package.json`에 **이미 있다**(`react-native-svg` 15.15.4 · `reanimated` 4.5.3 · `worklets` 0.10.0). SVG를 DOM으로 유지한 채 파츠를 다룰 수 있어 **부분 리깅(D33)에 유리** |
| Skia | ❌ gromo `package.json`에 **없다**(문자열 0건). `catsoup-clone-plan.md` §3·P4는 Skia를 계획했으나, 실제로 만든 `catsoup-rn` 프로토가 **불필요 판정하고 명시적으로 제거**했다 → `decisions-overridden.md` |
| PixiJS | ❌ `catsoup-lab`의 웹 랩 전용. 프로덕션 스택이 아니다 |

**주의 — 파이프라인 선택이 리깅 가능 여부를 가른다.** `catsoup-lab`은 SVG를 로드 시점에
**240×240 비트맵으로 굽기 때문에 런타임에 파츠 접근이 불가능하다**(`catsoup-lab/src/render/assets.ts`).
같은 방식을 RN에 가져오면 D33이 불가능해진다. **SVG를 DOM으로 유지하는 경로를 택해야 한다.**

## 3. 애니메이션 (D33 · D34 · D36)

### 3.1 as-is 실측

| 층 | 상태 |
| --- | --- |
| 에셋 | `<g>` **0개** · `id` **0개** · `class` **0개**. 20~30개 path가 그룹 없이 평면 나열. 파츠 구분자는 **HTML 주석뿐**이고 래스터화·SVGO 첫 단계에서 소멸 |
| 포즈 4종 | 머리·몸통은 좌표 거의 동일(±2px). **팔과 얼굴은 완전히 새로 그린 path.** 눈이 `ellipse`↔`path`로 타입이 바뀌어 **보간 불가, 스왑만 가능** |
| `catsoup-lab` | 고양이 1마리 = Sprite 1개. 모션 = 포즈 텍스처 즉시 교체 + 스프라이트 통짜 squash/stretch·기울기 + **위치 순간이동**(보간·걷기 없음) |
| `catsoup-rn` | **캐릭터 애니메이션 0.** 정지 PNG. 모션은 카메라 팬/줌뿐 |
| `ui55`·`ui56` | 캐릭터 모션 = `bob` **하나**(위아래 6px, 3.2초) |
| `ui57` | **캐릭터 상시 모션 없음.** 등장 트랜지션만 |

**즉 현재 에셋은 리깅된 캐릭터가 아니라 정지 일러스트이고, 세 시안이 구현한 캐릭터 모션은
"위아래 까딱임" 하나다.**

### 3.2 to-be — 부분 리깅

- **대상**: `assets/chars/cat/focus.svg` **1파일**. `chars-hq`가 아니라 **일반 벌**을 쓴다 — HQ는 파츠가 25→31개로 늘어 리깅 난도만 오르고 결과는 같다
- **파츠 분해**: `head` / `body` / `arm-l` / `arm-r` / `book` / `tail` / `face`
- **피벗**: 어깨 2 + 책등(spine) 1 = **3곳**. 현재 SVG에 관절 좌표가 전혀 없으므로 **신규 정의**
- **추가 작업**: 팔을 분리하면 드러나는 몸통 실루엣 보강
- **움직이는 것**: 팔 미세 회전 + 책장 넘김 + 호흡. **그 이상은 하지 않는다**
- **나머지 전부**: 포즈 스왑 + 통짜 transform

**D32(고양이만) 덕에 종족 차분이 사라져 대상이 딱 한 파일이다.**

### 3.3 LOD (D34)

부분 리깅이면 같은 화면에 "관절이 움직이는 고양이"와 "까딱이기만 하는 고양이"가 섞인다.
집중 공간 전용 화면에서는 전부 앉아 있어 문제없지만, **광장 전경에서 집중 공간이 같이 보이면
품질 차이가 한눈에 드러난다.**

➡️ C안의 줌 카메라를 이용해 **광장 전경(줌아웃)에서는 리깅 off / 집중 공간 진입(줌인)에서만 on.**

### 3.4 범위 정정 (D36)

컨셉 문구 *"고양이가 의자에 앉아 **책을 넘기는** 모션"*은 **집중 공간 화면(줌인) 한정**이다.
광장과 다른 건물 앞에서는 **포즈 표시만** 한다. 문서·기획서에서 이 문구를 쓸 때 범위를 명시한다.

### 3.5 공수

| 항목 | 소요 |
| --- | --- |
| 에셋 파츠 그룹핑 + 피벗 정의 + 실루엣 보강 (1파일) | 0.5~1일 |
| RN 캐릭터 렌더 컴포넌트 (포즈 스왑 + transform) | 2~3일 |
| 부분 리깅 런타임 + 튜닝 | 2~3일 |
| **소계 — 캐릭터 렌더** | **4~6일** |
| presence 배선 · 하트비트 · 건물 앵커 좌표 · 다인원 배치 규칙 | **별도 산정** |

**공수의 본체는 애니메이션이 아니라 배선 쪽이다.** 특히 D13(정원 무제한)으로 광장에
수십 마리가 설 수 있어 **배치 규칙**이 별도 설계 항목이다.

### 4.3 텍스트 대비 규칙 (2026-09-08 추가 — ui58 design review)

**역설계 팔레트의 브라운은 크림 배경 위에서 WCAG AA를 넘지 못한다.** 실측:

| 색 | 용도(기존) | `#F5EED8` 위 대비 | 판정 |
| --- | --- | --- | --- |
| `#9B7967` (`--muted`) | 본문 | **3.4:1** | ❌ AA 미달 |
| `#837574` (`--ink`) | 본문 | **3.85:1** | ❌ AA 미달 |
| `#8A6F5E` (`--line`) | 외곽선 | 3.97:1 | ❌ 본문 불가(선은 OK) |
| `#7C6553` (`--ink-soft`) | 보조 본문 | 4.6:1 | ✅ |
| `#6E5A4C` (`--ink`) | 본문·제목 | **5.5:1** | ✅ |
| `#4F6E35` (`--green-ink`) | 강조 녹색 | 5.0:1 | ✅ |

**규칙**: 본문·라벨 텍스트는 **`#6E5A4C` 이상**을 쓴다. `#9B7967`·`#837574`·`#8A6F5E`는
**선·테두리·장식 전용**이며 텍스트 색으로 쓰지 않는다.
`catsoup.design.md`의 "외곽선 딥브라운 계열"은 말 그대로 **외곽선** 규격이지 본문 색이 아니다.

**포커스 표시**: `--butter`(`#F9E7B7`) 단독 아웃라인은 크림 배경에서 **1.06:1**로 보이지 않는다.
`outline:3px solid #6E5A4C` + butter 헤일로 이중 링을 쓴다(밝은/어두운 배경 양쪽 대응).

**터치 타깃**: 44px 하한. 캡션 텍스트 12px 하한(숫자 배지만 11px 허용).

**이모지 금지**: 손그림 벡터 월드에 시스템 이모지를 섞지 않는다 — OS마다 렌더가 달라
